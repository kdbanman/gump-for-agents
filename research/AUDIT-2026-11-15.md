auditor agent: one core of a shared 4-core machine, about two hours, nothing longer than about ten minutes per

Conventions. Commands run from the repo root unless a `cd` is shown; `G=engine/target/release/gump`. **"tree"**
means `research/scratch/audit_c/tree`, a copy of the scripts' directories (`research/{atlas,clockwork,peeling,
theory/thin,theory/exponent,theory/swarm/exam}`, `research/toy2d/t2d.c`, `reference/*.py`) made with `cp -r`,
with symlinks in `tree/research/scratch/` to the producers' raw files where a script reads them. It was used
wherever a script writes into a committed directory or into a producer's scratch file, or caches its runs there
(so a re-run would be skipped); the scripts resolve their paths from their own location, so in the tree they read
and write only the tree. No code was changed. Bulk output is in `research/scratch/audit_c/` (git-ignored).
"Same seeds" means the run used the seeds the producer used, so it checks the code and the recorded numbers, not
the statistics; "fresh seeds" means new ones. My helper scripts (analysis only, no new experiments) are in
`research/audit/c_rows/`.

## Rows that differ, and the likely cause

- **P4.** ξ = 0.68 ± 0.01 cannot be reproduced as stated: no script or note records the Ornstein–Zernike fit
  (range, weights). Fits of the OZ form to sk.py's spherical S(k) give ξ from 0.63 to 0.92 depending on the k range
  and on the snapshot set (producer's `sk64.json`: 0.63–0.65; mine, with snapshots R = 1–12 of which R ≥ 5 differ
  from the producer's: 0.72–0.92), and the form does not fit the full range (χ² 40,484/36 with sk.py's errors).
  The quoted ±0.01 is far below this systematic spread. The isotropy statement "agrees within errors" also fails
  by sk.py's own errors (cones vs sphere χ² 54–428 on 10–11 bins at k ≤ 1.5 in both data sets). Part of that may
  be the error formula: `sk.py` divides the scatter of the snapshot-averaged S over a bin's modes by
  √(modes × snapshots), which counts the snapshots twice (errors ≈ √12 ≈ 3.5× too small); with errors 3.5× larger,
  the low-k cones are still off by χ² ≈ 4–35 on 10–11 bins. Suggested: commit the fit, fix or justify sk.py's error,
  and grade ξ by its range dependence.
- **ZL2.** The claim's summary "others ≤ 2.1 × 10⁻³ (symmetric R38; the rest ≤ 2 × 10⁻³)" omits fwslab 4×9×8, whose
  all-ages bound is 4.2 × 10⁻³ (`zombies.py`; the README table under "Zombie lives" states the same 4.2 × 10⁻³). Its
  statistical error is 0.042, so nothing depends on it; the ledger sentence is a transcription slip. Also,
  `zombies.py` computes a bound (1.2 × 10⁻¹) for fwslab 5×6×8 (1.77 mean lives), which the README and the claim list
  among the runs "shorter than about one mean life" with no bound: consistent in substance, but the word "about"
  carries it.
- **Window-dependent numbers (not counted as differing).** F2 plateau heights (ratios 0.770, 0.604, 0.454 over
  whole plateaus vs claimed 0.79, 0.61, 0.48) and P6's {110} speed (0.165 only for fit windows ending ≤ 80 gens;
  0.154 over 60–110; the {110} front decelerates) depend on an averaging window that is not recorded. F11's fit
  coefficients come out as claimed only when weighted by the firewall-first counts (unweighted: −2.00 + 0.533·N·m
  + 0.356·N); the weighting is not stated.
